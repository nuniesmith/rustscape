## 📦 Source Code Organization (`src/`)

### Entry Point
- **`main.js`** - Initializes Three.js, game loop, and core systems

### Cache System (`src/cache/`)
- **`CacheReader.js`** - Reads RuneScape Build 560 cache files
- **`ModelParser.js`** - Parses 3D model geometry and textures

**Purpose:** Load authentic RuneScape assets from cache

### Entities (`src/entities/`)
- **`PlayerModel.js`** - Player rendering with equipment system
- **`NPC.js`** - NPCs with AI behaviors (idle, wander, follow, hostile)

**Purpose:** Game entity classes with behavior and rendering

### Rendering (`src/rendering/`)
- Currently empty - reserved for future rendering utilities
- Will contain: terrain generation, lighting, effects, etc.

### Utils (`src/utils/`)
- **`constants.js`** - Centralized game configuration
  - Game settings (FPS, tick rate, etc.)
  - Cache configuration (archive IDs, model IDs)
  - UI configuration (dimensions, layouts)
  - Colors (RS theme colors)
  - Network packet types
  - Helper functions (XP calculations, combat level)

**Purpose:** Single source of truth for all constants

## 🌐 Public Files (`public/`)

## ⚙️ Build Configuration (`vite.config.js`)

### Key Settings

**Root Directory:**
```javascript
root: "public"  // Serve from public/ directory
```

**Path Aliases:**
```javascript
{
  "@": "./src",
  "@cache": "./src/cache",
  "@entities": "./src/entities",
  "@rendering": "./src/rendering",
  "@utils": "./src/utils",
  "@assets": "./assets"
}
```

**Usage Example:**
```javascript
import { PlayerModel } from "@entities/PlayerModel.js";
import { GAME_CONFIG } from "@utils/constants.js";
```

**Build Output:**
```javascript
outDir: "../dist"  // Build to dist/ directory
```

**Public Directory:**
```javascript
publicDir: "../assets"  // Copy assets/ to dist/
```

## 📝 Import Path Examples

### Using Path Aliases (Recommended)
```javascript
// Old way (relative paths)
import { PlayerModel } from "./entities/PlayerModel.js";
import { CacheReader } from "./cache/CacheReader.js";

// New way (path aliases)
import { PlayerModel } from "@entities/PlayerModel.js";
import { CacheReader } from "@cache/CacheReader.js";
import { GAME_CONFIG } from "@utils/constants.js";
```

### Benefits of Path Aliases
- ✅ No more `../../../` path hell
- ✅ Clear module organization
- ✅ Easy to refactor
- ✅ Works in both dev and production

## 📊 Code Organization Best Practices

### ✅ DO:
- Keep related code in the same directory
- Use path aliases for imports
- Centralize constants in `constants.js`
- Separate CSS from HTML
- Use semantic HTML structure

### ❌ DON'T:
- Put inline styles in HTML
- Use relative paths like `../../../`
- Hardcode magic numbers
- Mix concerns (logic + presentation)
- Put everything in one file

## 💡 Quick Reference

### Add New Module
1. Create file in appropriate `src/` subdirectory
2. Export your classes/functions
3. Import using path alias: `import { MyClass } from "@subdir/MyClass.js"`

### Add New Stylesheet
1. Create CSS file in `assets/styles/`
2. Import in `index.html`: `<link rel="stylesheet" href="../assets/styles/new.css">`

### Add New Asset (Image/Font)
1. Place file in `assets/images/` or `assets/fonts/`
2. Reference in CSS: `background-image: url('../images/sprite.png')`
3. Or in JS: `import spriteUrl from "@assets/images/sprite.png"`

### Update Configuration
1. Edit `src/utils/constants.js`
2. Export new constant
3. Import where needed: `import { NEW_CONFIG } from "@utils/constants.js"`
